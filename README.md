Litematica (panyaaa256 fork)
============================

[sakura-ryoko/litematica](https://github.com/sakura-ryoko/litematica) のフォークです。
本家の機能はそのままに、**図面検証 (Schematic Verifier) と建材リストの強化**、および **Servux によるサーバーサイド処理** を追加しています。

サーバーサイド処理を使うには、サーバーにフォーク版 Servux
([panyaaa256/servux](https://github.com/panyaaa256/servux)) が必要です。
Servux がないサーバーやシングルプレイでも、それ以外の追加機能は使えます。

追加機能
--------

### Servux によるサーバーサイド処理

Litematica は、クライアントが読み込んでいるチャンク (描画距離の内側) しか見ることができません。
また、開いていないコンテナの中身はクライアントに送られてきません。
次の 3 つは処理をサーバーに任せることで、この制約をなくします。

サーバーの Servux が対応しているかどうかは自動で判定します。
対応していないサーバーでは、ボタンを表示しないか、従来どおりクライアント側で処理します。

#### 図面検証

図面検証 GUI に **「開始 (サーバー)」** ボタンが追加されます (Servux が対応している場合だけ表示)。

- 描画距離に関係なく、配置全体を検証できます。
- 結果は通常の検証と同じ GUI に表示され、無視リストやブラック / ホワイトリストなどの表示設定もそのまま効きます。
- `verifierCheckContents` を有効にすると、通常の分類に加えて **「中身違い (Wrong Contents)」** が表示されます (既定は無効)。チェストなどコンテナの中身が図面と違う位置です。通常の検証はブロックの状態しか比べないため、空のチェストも「正しい」扱いになります。
  - 既定ではコンテナ 1 つを 1 行で表示し、行の右端にはそのコンテナの座標を表示します。`verifierGroupWrongContents` を有効にすると、他の分類と同じくブロックごとにまとめて表示します。
  - 行にカーソルを合わせると、図面側と実際のインベントリを並べて表示し、違いの原因になっているスロットを赤く示します (既定の比較では、左がワールドに足りないアイテム、右がワールドに余計なアイテム)。まとめて表示している場合は、その中で最も近いコンテナを表示します。
  - 行を選択すると、ワールド内のその位置をハイライトします。
  - 無視すると、そのコンテナだけを無視します (同じ種類のコンテナすべてではありません)。
- 実行中は情報 HUD に進行状況 (処理済みチャンク数 / 全体) が表示されます。
- サーバーが読めなかったチャンク (未読み込み・未生成) は「未確認チャンク」として残ります。
- [エンティティの検証](#エンティティの検証)もサーバー上で行います。クライアント側と違って、エンティティのトラッキング範囲より遠くても調べられます。
  - エンティティ検証に対応した Servux (2026-09-22 以降) が必要です。古い Servux では、サーバー検証の結果にエンティティは含まれません。

#### 領域分析

設定 `analyzeUsingServux` (既定: 有効) が有効だと、領域分析 (Area Analyzer) をサーバー上で行います。

- 描画距離の外まで数えられます。
- **コンテナの中身を数えられます。** クライアント側の分析では、マルチプレイのサーバー上のコンテナはすべて空として数えられます。
- サーバーが対応していない場合は、警告を出してクライアント側で分析します。

#### 建材リスト

設定 `materialListUsingServux` (既定: 無効) を有効にすると、配置の建材リストをサーバー上で作成します。

- クライアント側の建材リストは、描画距離の外をすべて「不足」として数えます。サーバー側なら、実際に置かれているブロックと突き合わせた正しい不足数になります。
- リストを更新するたびに図面をサーバーへアップロードするため、既定では無効にしています。大きな図面はアップロードの上限を超えて送信できないことがあり、その場合はクライアント側で作成します。
- 「建材リストで状態を無視」 (`materialListIgnoreState`) の設定はサーバー側にも引き継がれます。
- サーバーが対応していない場合は、警告を出してクライアント側で作成します。

領域分析・建材リストの実行中は、情報 HUD に進行状況が表示されます (建材リストでは途中までの不足数も表示)。
サーバーが読めなかったチャンクがあった場合は、その分が結果に含まれていないことを警告で知らせます。

### 図面検証の強化

#### エンティティの検証

図面にあるエンティティが、ワールドに置かれているかを検証します。
対象は額縁・絵画・防具立て・トロッコ・ボートなどです (モブ、ドロップアイテム、経験値オーブ、飛び道具は対象外)。

- 検証結果に **「不足エンティティ (Missing Entities)」** の分類が追加されます。
- 結果の一覧で選択したエンティティは、発光の輪郭で強調表示されます (色: `verifierEntityHighlightColor`)。
- 図面の位置から `verifierEntityPositionTolerance` ブロック以内にあれば、正しく置かれているとみなします。
- `verifierCheckEntities` を無効にすると、エンティティを検証しません (「不足エンティティ」のボタンと一覧も表示されません)。

クライアントがエンティティを受け取れるのは、エンティティの種類ごとの「トラッキング範囲」の内側だけです (額縁・絵画・防具立ては 10 チャンク、トロッコは 8 チャンク)。
これは多くの場合、描画距離よりずっと短い範囲です。
そのため、この範囲より遠いエンティティは「不足」ではなく **「未確認」** として扱い、プレイヤーが近づいた時点で検証します。
未確認の件数は、結果一覧の「不足エンティティ」の見出しに表示されます。

- サーバーの設定 `entity-broadcast-range-percentage` でトラッキング範囲が狭められている場合は、その差の分のエンティティが「不足」と表示されることがあります。

サーバー検証 (「開始 (サーバー)」) では、この制限はありません。
サーバーはすべてのエンティティを見られるので「未確認」はなく、見つからなければそのまま「不足」になります。

- 判定のルール (対象になるエンティティ、`verifierEntityPositionTolerance`) はクライアント側の検証と同じです。
- 検証後にエンティティを置き直すと、クライアントに届いた時点で「不足」の一覧から消えます。
- 遠くの不足エンティティを選択した場合、強調表示は、近づいて図面のエンティティが表示された時点で付きます。

#### ブラックリスト / ホワイトリスト

特定のブロックや、ブロックの特定の状態 (プロパティ) を検証から除外できます。

- `verifierListType` で使うリストを選びます: `None` (リストを使わない) / `Blacklist` / `Whitelist`
- `Blacklist` のときは `verifierBlacklist` のエントリを無視し、`Whitelist` のときは `verifierWhitelist` のエントリだけを検証します。
- 変更は次に検証を開始したときに反映されます。

エントリの書式:

| 書式 | 意味 |
|---|---|
| `minecraft:lever` | このブロックを対象にする |
| `#minecraft:buttons` | このタグのブロックを対象にする |
| `minecraft:observer[powered=*]` | このブロックの、指定したプロパティの違いだけを対象にする (カンマ区切りで複数可、`=*` はすべての値) |
| `[waterlogged=*]` | すべてのブロックで、指定したプロパティの違いを対象にする |
| `minecraft:lever[powered=true]` | 状態が指定した値にすべて一致する位置を対象にする |
| `key!=value` | 条件を反転する (指定した値以外に一致) |

- タグ指定・全ブロック指定でも、プロパティの条件を使えます (例: `#minecraft:candles[lit=*]`、`[waterlogged=true]`)。
- ブロックと状態の指定は図面側の状態と照合します。図面が空気の位置 (余計なブロック) だけは、ワールド側の状態と照合します。
- ホワイトリストにブロックのエントリが 1 つもない場合は、すべてのブロックを検証します。
- 無効なエントリは無視されます。

#### 未読み込みチャンクの強調表示

`highlightUnloadedChunks` を有効にすると、図面検証・領域分析・建材リスト・図面保存がまだ読み込みを待っているチャンクを枠で表示します。
検証がなかなか 100% にならないとき、どこが原因かがひと目で分かります。

- 枠の上端は `unloadedChunksMaxY`、色は `unloadedChunksHighlightColor` で変えられます。
- ホットキーを割り当てて切り替えられます。

### 建材リストの強化

#### エンティティ・コンテナの中身を含める

建材リスト GUI に **「エンティティ」「コンテナ」** のボタンが追加されます。
図面の建材リスト、配置の建材リスト、領域分析のいずれでも使えます。

| 値 | 意味 |
|---|---|
| なし (None) | 含めない (従来どおり) |
| 含める (Include) | ブロックのリストに加える |
| のみ (Only) | それだけを一覧する |

- エンティティは、クリエイティブモードでピックしたときに手に入るアイテムとして数えます。牛などのモブはスポーンエッグ、額縁・絵画・防具立て・トロッコ・ボートはそれぞれのアイテム、リードの結び目はリードになります。
  - 額縁は、中に入っているアイテムではなく額縁として数えます。
  - 対応するアイテムがないエンティティ (マーカー、ディスプレイエンティティなど) は数えません。
- コンテナの中身は、入れ子のシュルカーボックスやバンドルの中身まで数えます。
- 配置の建材リストでは、エンティティとコンテナの中身は常に「不足」として数えます (ワールド側と突き合わせないため)。
- クライアント側の領域分析では、シングルプレイ以外はコンテナの中身を読めません。サーバー上のコンテナを数えるには `analyzeUsingServux` を使ってください。

#### ホットキー

| ホットキー | 説明 |
|---|---|
| `toggleMaterialListInfo` | 建材リストの情報 HUD の表示を切り替えます。建材リストがまだない場合は、選択中の配置の建材リストを作成して表示します |
| `toggleMaterialListType` | 建材リストの対象 (すべてのブロック / 描画中のレイヤーのみ) を切り替え、リストを作り直します |

どちらも既定ではキーが割り当てられていません。

### 修正

- 描画レイヤー (Render Layers) の範囲外にある図面のエンティティが表示されていた問題を修正しました。
- 描画を無効にしたサブリージョンも図面検証の対象になっていた問題を修正しました。
- タスク管理画面から図面検証を中止したとき、未確認チャンクの表示が残る問題を修正しました。
- 検証結果で、アイテムに変換できないブロックの名前が「空気」と表示され、列の幅がずれる問題を修正しました。
- Servux とのバージョン差で知らない種類のパケットを受け取ったとき、接続が切れていた問題を修正しました (警告を出して無視します)。
- アップロードの上限を超える図面でサーバー側の図面検証を始めたとき、応答を待ったまま止まる問題を修正しました。

追加された設定
--------------

| 分類 | 設定 | 既定 | 説明 |
|---|---|---|---|
| Generic | `analyzeUsingServux` | 有効 | 領域分析を Servux でサーバー上で行う |
| Generic | `materialListUsingServux` | 無効 | 配置の建材リストを Servux でサーバー上で作成する |
| Generic | `verifierListType` | `Blacklist` | 図面検証で使うリスト (`None` / `Blacklist` / `Whitelist`) |
| Generic | `verifierBlacklist` | 空 | 図面検証で無視するブロック / プロパティ |
| Generic | `verifierWhitelist` | 空 | 図面検証で検証するブロック / プロパティ |
| Generic | `verifierCheckContents` | 無効 | サーバーサイド検証でコンテナの中身も比較する |
| Generic | `verifierCheckEntities` | 有効 | 図面検証でエンティティも検証する |
| Generic | `verifierGroupWrongContents` | 無効 | 中身違いをブロックごとにまとめて表示する |
| Generic | `verifierEntityPositionTolerance` | `0.1` | エンティティが図面の位置からずれていても正しいとみなす距離 (ブロック、0〜8) |
| Visuals | `highlightUnloadedChunks` | 無効 | 読み込み待ちのチャンクを強調表示する |
| Visuals | `unloadedChunksMaxY` | `128` | 強調表示の枠の上端の Y 座標 |
| Colors | `unloadedChunksHighlightColor` | `#30FF8800` | 読み込み待ちチャンクの枠の色 |
| Colors | `verifierEntityHighlightColor` | `#FFAA00AA` | 選択した不足エンティティの輪郭の色 |
| Hotkeys | `toggleMaterialListInfo` | なし | 建材リストの情報 HUD を切り替える |
| Hotkeys | `toggleMaterialListType` | なし | 建材リストの対象を切り替える |

ビルド
------

JDK 25 でビルドできます。

```
git clone https://github.com/panyaaa256/litemafork.git
cd litemafork
git checkout 26.2   # 1.21.11 版は git checkout 1.21.11
./gradlew build
```

ビルドした jar は `build/libs/` にできます。
現在、ビルド済みの配布ファイル (Releases) はありません。
